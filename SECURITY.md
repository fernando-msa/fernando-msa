# Security Policy

## Supported Versions

Security updates are actively applied to the default branch (`main`) and latest releases.

| Version | Supported          |
| ------- | ------------------ |
| 1.x     | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

Security and integrity are top priorities for this repository and associated software projects.

If you believe you have discovered a security vulnerability in this project, please follow responsible disclosure practices:

1. **GitHub Private Vulnerability Reporting (Preferred)**:
   - Navigate to the [Security Advisories tab](https://github.com/fernando-msa/fernando-msa/security/advisories) on this repository.
   - Click on **"Report a vulnerability"** to submit a confidential report directly to the maintainer.

2. **Direct Contact**:
   - If GitHub advisory submission is unavailable, please open a confidential inquiry or reach out via LinkedIn: [Fernando Santos](https://www.linkedin.com/in/fernando-msa/).

### What to Include in Your Report

To help us investigate and reproduce the issue efficiently, please include:

- A clear description of the vulnerability and its potential impact.
- Step-by-step instructions to reproduce the issue (proof of concept, scripts, or relevant logs).
- Affected files, packages, or workflows.
- Any suggested fixes or remediations if available.

### Response Timelines

- **Initial acknowledgment**: within 48 hours.
- **Triage and impact assessment**: within 5 business days.
- **Remediation and disclosure**: we will coordinate a fix and release notes in a timely manner before public disclosure.

Please do not disclose the vulnerability publicly before a fix is published. Thank you for helping keep our software secure!
